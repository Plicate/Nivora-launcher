# Nivora Launcher

**Универсальный лаунчер Minecraft: Java, Bedrock и серверы — в одном окне**

Современный интерфейс на Vue 3, производительное ядро на Rust, честное
отношение к лицензиям и данным. Bedrock — только Windows и Linux; всё остальное работает на трёх десктопных платформах.

## О лаунчере

Nivora запускает **Java-версию Minecraft** (vanilla, Fabric, Quilt, Forge,
NeoForge), **серверные ядра** (Paper, Purpur, Pufferfish, Folia, Spigot,
Leaf, Patina) и **Minecraft Bedrock** — на Linux через встроенный
BedrockOnLinux, на Windows через официальный «Minecraft for Windows» из
Microsoft Store. Никаких переупаковок игры: Bedrock всегда ставится из
официальных источников под лицензией вашего аккаунта.

- **Экземпляры вместо одной установки** — изолированные папки, группы, теги,
  иконки, время игры, дублирование, ZIP-экспорт; ярлыки экземпляров на
  рабочем столе и в меню приложений (`.lnk` / `.app` / `.desktop`),
  запускающие лаунчер и сразу нужный экземпляр, плюс экспорт списка модов
  в Markdown/CSV/текст.
- **Каталоги** — моды, ресурспаки, шейдеры, датапаки и модпаки с Modrinth,
  CurseForge, FTB, Technic; серверные плагины с Modrinth, Hangar, Spiget и
  GitHub Releases.
- **Аккаунты** — Microsoft (device-code вход, Xbox Live/XSTS, скины и плащи)
  и ely.by; несколько аккаунтов с alias-именами. Пароли не хранятся никогда:
  токены лежат в системном хранилище секретов.
- **Игровой оверлей** (`Shift+Tab`) — моды, время сессии, системные метрики,
  запись видео (`F7`) поверх игры.
- **Рабочее пространство** — live-консоль, снапшоты, галерея скриншотов,
  файловый менеджер, метрики CPU/RAM/диск.
- **Персонализация** — центр тем в стиле Blender/Unity: цвета, формы,
  обои, шрифты, компоновка, анимации; темы из GitHub-каталога.
- **Собственные файловые окна** — просмотр папок и выбор файлов происходят
  в диалогах лаунчера, а не в проводнике ОС и не в системных пикерах;
  контекстное меню — своё, с живыми действиями для экземпляров, аккаунтов
  и модпаков.
- **Нативное Rust-ядро** — установка версий, метаданные (версии Mojang,
  загрузчики, ядра серверов), Bedrock, управление серверами
  (запуск/стоп/консоль), сеть серверов (диагностика белого IP, UPnP-проброс,
  счётчики TCP-трафика), файлы и логи экземпляров, темы, резервные копии и
  проверка обновлений выполняются внутри процесса Tauri через
  `rust_engine`; Python-воркер обслуживает только оставшиеся операции
  каталогов и плагинов. Прогресс нативных загрузок виден в панели ACTIVITY
  в реальном времени.
- **Самообновление** — проверка и установка обновлений прямо из лаунчера
  (Настройки → Самообновление); фид — `latest.json` из GitHub Releases,
  пакеты подписаны ключом minisign. На Linux автообновление работает для
  AppImage; deb/rpm обновляются переустановкой пакета.
- **Прочее** — WebDAV-синхронизация данных, HTTP/SOCKS5-прокси, профили
  настроек, ограничения плагинов без исполнения кода, CLI и `doctor`
  для диагностики.

Полный список возможностей — в [docs/FEATURES.ru.md](docs/FEATURES.ru.md).

## Установка

| ОС | Способ |
|---|---|
| **Windows 10/11** | Установщик `.exe` (NSIS). Требуется WebView2 (ставится автоматически). Bedrock — официальный «Minecraft for Windows» из Microsoft Store: лаунчер сам предложит установку через winget или страницу Store. |
| **Debian/Ubuntu** | Пакет `.deb` (`python3` ставится как зависимость). |
| **Fedora/RHEL** | Пакет `.rpm`. |
| **Arch/CachyOS** | Сборка пакета скриптом `scripts/build_arch_package.sh`. |
| **macOS 10.15+** | Образы `.dmg` под Apple Silicon и Intel. Не нотаризованы: первый запуск скачанного приложения — правый клик → «Открыть» или `xattr -dr com.apple.quarantine "Nivora Launcher.app"`. |

Готовые пакеты публикуются на странице Releases. На macOS обновления
ручные: фид самообновления требует подписи Developer ID, которой нет —
без неё артефакты апдейтера не собрать.

> **Windows предупреждает при запуске:** установщик не подписан EV-сертификатом,
> поэтому SmartScreen может показать «Система Windows защитила ваш компьютер» —
> «Подробнее» → «Выполнить в любом случае». Это норма для неподписанных
> open-source сборок; целостность всего скачанного лаунчер проверяет сам.

> **Linux + Wayland:** отдельное окно оверлея поверх чужой игры Wayland не
> позволяет — оверлей открывается внутри окна лаунчера (кнопка в верхней
> панели, назначенная клавиша или пункт в трее). На X11 работает поверх игры.

## Сборка из исходников

Архивы исходников не наращиваются поверх друг друга: распаковывайте в
**чистый каталог** (сначала `rm -rf nivora-launcher`) — иначе файлы,
удалённые в новой версии, остаются на месте и ломают сборку TypeScript.

```bash
git clone <repo> nivora-launcher && cd nivora-launcher
# для архива то же правило:
# rm -rf nivora-launcher && tar -xzf nivora-launcher-stage4.tar.gz

# Windows (из WSL/Linux-окружения с кросс-инструментами или из Windows)
bash scripts/build_windows_exe.sh

# Linux
bash scripts/build_deb.sh        # или rpm/arch — см. scripts/build_all.sh

# macOS
bash scripts/build_macos_app.sh  # MACOS_ARCH=arm64|x86_64|both
# → dist/macos/Nivora-Launcher_<версия>_<arch>.dmg (+ .app.zip, SHA256SUMS)

# Всё сразу для текущей ОС
bash scripts/build_all.sh         # проверяет артефакт каждой цели

# Разработка
cd frontend && npm install && npm run tauri dev
```

Для Python-бэкенда нужен Python 3.10+. Голый `npm run tauri build` без
сборки бэкенда годится для разработки (лаунчер откатывается на системный
`python3`), но в релизные пакеты бэкенд всегда вшит — его собирает
PyInstaller перед упаковкой. Проверка перед релизом:

```bash
cargo test --locked                                # Rust-ядро
python3 -m unittest discover -s tests -q           # Python-часть
cd frontend && npm run build                       # vue-tsc + vite
```

## Minecraft Bedrock

- **Windows** — только официальный «Minecraft for Windows» из Microsoft Store.
  Установка через winget с фолбэком на страницу Store, запуск по протоколу
  `minecraft://`, контент — в `com.mojang` пакета.
- **Linux** — встроенный BedrockOnLinux **2.2.9** (SHA-256 закреплён в
  исходниках, целостность проверяется при каждом запуске). Игра загружается
  с CDN Microsoft Store **под вашей лицензией**: аккаунт, который входит в
  Nivora, обязан владеть Minecraft.
- Вход Microsoft **один на все экземпляры** Bedrock (общее хранилище лицензии
  xodus) — повторные регистрации устройства не создаются.
- Без входа игра не стартует: её файлы зашифрованы лицензией аккаунта-владельца.
  Карточка «Лицензия Microsoft Store» в воркспейсе всегда показывает статус.
- Воркспейс Bedrock поддерживает консоль сессии с архивом логов, скриншоты
  игры, снапшоты контента (паки/аддоны/миры) и файловый менеджер профиля.

## Архитектура

```
frontend/          Vue 3 + TypeScript + Tauri 2 (GUI)
  src-tauri/       Rust-движок: bootstrap, настройки, файлы/логи экземпляров,
                   группы, плагины, Bedrock, оверлей, загрузки, аккаунты,
                   ely.by, анализ шейдеров, глобальный поиск, импорт миров,
                   оптимизация экземпляров, каталог Modrinth
  cpp-turbo/       nivora-turbo — пакетный SHA-256 и скан jar-манифестов
                   (C++, только системный zlib)
  go-modcat/       nivora-modcat — каталог Modrinth на Go: поиск, карточки
                   проектов и параллельная проверка обновлений
  java/            ModScan.java — глубокий разбор модов: манифесты всех
                   форматов и требуемая версия Java по class-файлам
nivora_launcher/   Python-воркер: импорт/экспорт модпаков, облако,
                   инфраструктура плагинов — только фоновая работа
scripts/           Сборка пакетов (exe/deb/rpm/arch/app+dmg), диагностика
docs/              Документация по подсистемам
```

Старт приложения целиком идёт на Rust-движке: bootstrap, настройки и вкладки
«Файлы»/«Логи» вообще не поднимают Python. Воркер запускается лениво — только
для операций, которые движок ещё не перенял (каталоги, сборка модпаков,
WebDAV-синк), поэтому долгая загрузка больше не выстраивает очередь из
запросов интерфейса. Тяжёлое хеширование внутри воркера (манифесты облака)
отдано бинарнику nivora-turbo: пул потоков с аппаратным SHA, сверка с
эталонными векторами при сборке, откат на hashlib при его отсутствии.

Почему языки распределены именно так: всё внутри процесса — Rust (без второй
рантайм-среды и пауз GC, прямой доступ к API Tauri). Остальные языки живут
там, где процесс-хелпер окупается: C++ (nivora-turbo) — батч-операции над
файлами (SHA-256, скан jar-манифестов) без рантайма в комплекте; Go
(nivora-modcat) — сетевой каталог Modrinth с конкурентными запросами;
Java (ModScan.java) — родная среда для jar: разбор манифестов и
class-файлов ради честной «требуемой версии Java». Отсутствие любого
хелпера не ломает запуск — движок откатывается на прежний путь.

Обе части помечены меткой сборки — при рассинхроне лаунчер показывает
предупреждение вместо непредсказуемого поведения.

Установка экземпляров качает всё сразу: клиент, библиотеки, ассеты и
лог-конфиг идут четырьмя параллельными стадиями, внутри которых библиотеки
идут пулом соединений, файлы больше 8 МиБ с известным хешем — сегментами
по нескольким соединениям, ассеты — удвоенным пулом; общий журнал
целостности не даёт стадиям затирать чужие записи. Анализ шейдеров читает
сами файлы пака: версии GLSL, профиль, compute-стадии и supportedVersions
превращаются в вердикт по каждой версии Minecraft, без догадок по названию
пака. Глобальный поиск (Ctrl+K) находит, в каком экземпляре установлен мод
(включая выключенные и по внутреннему имени из jar-манифеста), плагин,
мир, ресурспак или шейдер. Папки открываются во встроенном проводнике
лаунчера, включая импорт миров из локальной папки — системные диалоги
больше не нужны.

## Данные и приватность

- Каталоги данных: `nivora-launcher` в `%APPDATA%`/`%LOCALAPPDATA%` (Windows)
  или XDG-каталогах (Linux). Данные старого `trial-launcher` переносятся
  автоматически при первом запуске.
- Учётные данные — в системном хранилище (Credential Manager / keyring);
  пароли Microsoft вводятся на страницах Microsoft и в лаунчер не попадают.
- Телеметрии нет. Все запросы — только к официальным API (Mojang, Microsoft,
  каталоги модов) и вашему прокси/облаку, если вы их настроили.

## Диагностика

- «Диагностика оверлея» в настройках — пошаговый самотест (среда, окно,
  показ, always-on-top, глобальные клавиши).
- Windows: `scripts/collect_crash_report.bat` собирает логи в один файл
  (`%LOCALAPPDATA%\nivora-launcher\`).
- Сбои старта показываются диалогом с текстом ошибки, а не молча.
